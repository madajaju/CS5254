== Idempotency

[.text]
* Idempotency means repeating an operation does not change the result after the first success.
* It helps protect against retries, duplicates, and partial failures.
* Common examples include payment requests, job processing, and message consumption.

== Event Ordering

[.text]
* Event ordering determines how a system handles messages that arrive out of sequence.
* Ordering can be enforced globally, per partition, or per entity.
* The right strategy depends on throughput, latency, and correctness needs.

== State Machines

[.text]
* State machines model valid transitions between states.
* They prevent illegal actions by making transitions explicit.
* They are useful for workflows, payments, approvals, and async jobs.

== Debugging Async Systems

[.text]
* Async bugs often come from retries, duplicates, lag, and hidden failures.
* Good debugging starts with correlation IDs, logs, metrics, and traces.
* Reproducing message flow is often more useful than inspecting one service alone.
