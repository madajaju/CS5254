== Core Concepts: States

* Definition: Possible conditions (e.g., `DRAFT`, `CLEANING`).
* Importance: Must be explicit to trust under pressure.
* Mechanisms: Affected by state, timing, behavior, coordination.
* Failure: Ignoring leads to duplicate work, stale state.
* Design: Expose invariant, log transitions, repeat tests.

== Core Concepts: Transitions

* Definition: Valid paths between states.
* Importance: Must be explicit for system trust.
* Mechanisms: Affected by state, timing, behavior, coordination.
* Failure: Ignoring leads to duplicate work, stale state.
* Design: Expose invariant, log transitions, repeat tests.

== Worked Example: Problem Setup

* **Podcast Example**:
  * Transition: `INGESTED` + `CleanFinished` -> `CLEANED`.
  * Guard: Reject `Publish` event if `INGESTED`.
* **Order System**:
  * Can't `SHIPPED` unless in `PAID` state.

== Worked Example: Naive Implementation

* Operation sequence:
  * Actor performs operation.
  * System reads current state.
  * System applies transition.
  * System emits side effect.

== Worked Example: Failure Scenario

* Concurrent operations can:
  * Observe stale state.
  * Execute twice or arrive late.
  * Leave the workflow stuck.
* Failure reveals mismatch between design assumption and execution.

== Worked Example: Improved Design

* Name the invariant.
* Make transitions observable.
* Add controls:
  * Version checks
  * Idempotency keys
  * Coordination, retries, compensation

== Worked Example: Safer Design

* Improved design:
  * Proves invalid interleavings are rejected or contained.
  * Changes focus from hoping execution order to solid evidence.

== Failure Modes and Anti-Patterns

* **Symptom**: System passes happy-path demo.
  * **Detection**: Use stress tests.
  * **Correction**: Add failure-focused tests targeting the invariant.

* **Symptom**: Tool named, not property.
  * **Detection**: Ask which invariant is protected.
  * **Correction**: State the invariant first.

* **Symptom**: Vague evidence.
  * **Detection**: Reviewer can't reconstruct failures.
  * **Correction**: Capture structured evidence.

* **Symptom**: Fix changes behavior without baseline.
  * **Detection**: No before/after runs.
  * **Correction**: Preserve failing test.

== Trade-Off Analysis

[cols="1,1,1,1", options="header"]
|===
| Approach | Strengths | Weaknesses | When to Use
| Simple baseline | Easy to explain | Hides timing assumptions | First implementation
| Guarded transition | Protects core invariant | Requires careful modeling | Status changes
| Explicit coordination | Makes dependencies visible | Can cause deadlocks | Multi-object workflows
| Idempotent design | Handles duplicates | Requires control | Queues, retries
| Observability-first | Strong evidence | Adds instrumentation | Failure proof
|===
