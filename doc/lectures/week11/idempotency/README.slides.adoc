== Idempotent Operation
* Same input, no additional effect on repeat
* The real question is whether the state change is protected
* Retries, queues, and timing make the assumption visible
* Happy-path success can hide duplicate work
* Good design makes the critical transition explicit

== Trade-Off Table
[.stretch]
[cols="1,1,1,1", options="header", width="100%"]
|===
|Approach |Strength |Weakness |Use When
|Simple baseline |Easy to explain |Hides pressure assumptions |First pass
|Guarded state transition |Protects invariant |Needs careful modeling |Workflow steps
|Explicit coordination |Makes dependencies visible |Can bottleneck |Multi-object ordering
|Idempotent design |Handles duplicates |Needs keys or deduplication |Retries and queues
|===
