== Check-pointing
* Definition: Periodic state saving of workflows.
* Importance: Essential for trust under pressure.
* Mechanism: Object state, workflow timing, worker behavior
* Failure mode: Duplicate work, stale state, blocked progress
* Design implication: Expose invariant, log transitions, validate tests.

== Naive Implementation
* A naive design assumes operation happens once, in order, with current state.

```
actor performs operation
system reads current state
system applies transition
system emits side effect
```

== Failure Scenario
* Overlapped execution or delays can:
  * Observe stale state
  * Execute twice
  * Leave workflow stuck

== Improved Design Direction
* Name the invariant and make transitions observable.
* Implement controls like:
  * Version checks
  * Idempotency keys
  * State-machine guards

== Safer Design Benefits
* Moves from hoping execution order is correct to proving invariants are maintained.

== Failure Modes and Anti-Patterns
* Symptom: Passes happy-path test.
  * Detection: Add repeated runs, concurrent actors.
  * Correction: Add failure-focused test to target invariant.
  
* Symptom: Tool named, not design property.
  * Detection: Ask which invariant is protected.
  * Correction: State invariant, then chosen mechanism.

* Symptom: Evidence is vague.
  * Detection: Reviewer can't reconstruct failure.
  * Correction: Capture structured evidence linked to claims.

* Symptom: Fix changes behavior, no baseline comparison.
  * Detection: No before/after run.
  * Correction: Maintain failing test for rerun post-redesign.

== Trade-Off Analysis
[cols="1,1,1,1", options="header"]
|===
| Approach | Strengths | Weaknesses | When to Use
| Simple baseline | Easy to explain | Hides timing assumptions | First implementation
| Guarded transition | Protects invariant | Needs careful modeling | Status changes
| Explicit coordination | Makes dependencies visible | May cause bottlenecks | Multi-object workflows
| Idempotent design | Handles duplicates | Requires deduplication | Queues, async workers
| Observability-first | Strong evidence | Adds instrumentation | Design defense
|===
