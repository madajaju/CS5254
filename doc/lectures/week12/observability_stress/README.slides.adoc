== Comparison

[.column]
* Baseline
* Easy to explain
* Hides timing assumptions
* Passes one happy path

[.column]
* Stress-aware design
* Makes the invariant explicit
* Exposes latency and queue growth
* Supports repeatable failure tests

== Trade-Off Analysis

[.stretch]
[cols="1,1,1,1", options="header", width="100%"]
|===
|Approach |Strength |Weakness |Use Case
|Simple baseline |Fast to build |Hides pressure assumptions |First pass
|Guarded state transition |Protects invariant |Needs careful modeling |Workflow steps
|Explicit coordination |Shows ordering |Can bottleneck |Multi-object flows
|Idempotent retry-safe design |Handles duplicates |Adds key management |Queues and async work
|===
