== Trade-Offs
[.stretch]
[cols="1,1,1,1", options="header", width="100%"]
|===
|Approach |Strengths |Weaknesses |When to Use
|Simple baseline |Easy to explain and implement |Hides timing and pressure assumptions |First comparison point
|Guarded transition |Protects the invariant directly |Needs careful state modeling |Workflow state changes
|Explicit coordination |Makes dependencies visible |Can bottleneck or deadlock |Ordered multi-object work
|Idempotent design |Handles duplicates and partial failure |Needs keys and deduplication |Queues, retries, async work
|Observability-first |Strong evidence for review |Adds instrumentation work |Failure proof and defense
|===

== Practical Checklist
* Identify the invariant or progress property.
* Write one sequential scenario.
* Write one pressure scenario.
* Add operation IDs and entity IDs.
* Capture before/after evidence.
* Record assumptions, validation, and remaining risk.
