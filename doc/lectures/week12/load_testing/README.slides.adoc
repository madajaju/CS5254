== Trade-Off Analysis
[.stretch]
[cols="1,1,1,1", options="header", width="100%"]
|===
| Approach | Strengths | Weaknesses | When to Use

| Simple baseline | Easy to explain | Hides timing assumptions | First comparison point

| Guarded transition | Protects the invariant directly | Needs careful state modeling | Workflow steps and status changes

| Explicit coordination | Makes dependencies visible | Can add waiting or bottlenecks | Multi-object ordering

| Observability-first design | Produces strong evidence | Adds instrumentation work | Failure proof and defense
|===
