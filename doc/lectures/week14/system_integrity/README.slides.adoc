== Integrity Under Pressure
* A system may look correct on the happy path.
* Pressure reveals the hidden assumption.
* Integrity means the invariant still holds.
* The question is not only "does it run?"
* The question is "does it stay correct?"

== Pressures and Controls
[cols="1,1,1,1", options="header", width="100%"]
|===
|Pressure |What breaks |Useful control |Trade-off
|Concurrency |Ordering assumptions |State guard |More modeling effort
|Retries |Duplicate side effects |Idempotency key |Key management
|Load |Unbounded queues |Backpressure |Lower peak throughput
|Failure |Invisible recovery |Structured logs |Instrumentation cost
|===

== Practical Response
* Write the invariant first.
* Reproduce the failure with pressure.
* Capture structured evidence.
* Apply one control that preserves the invariant.
* Compare before and after runs.
* Defend the trade-off in the Integrity Packet
