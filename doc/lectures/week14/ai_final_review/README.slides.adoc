= AI Final Review: What Was Learned?
:revealjsdir: https://cdn.jsdelivr.net/npm/reveal.js

== The Lecture at a Glance

* AI can accelerate drafting, but it does not verify correctness.
* Concurrency pressure reveals hidden assumptions.
* Evidence must come from repeatable tests, logs, and traces.
* The engineer remains responsible for the invariant.
* The Integrity Packet records the defended conclusion.

== What the Topic Means

[.column]
* The lecture asks what was learned from using AI in a stateful concurrent system.
* The real question is whether the design still works under pressure.
* A good answer names the invariant, the failure evidence, and the correction.

[.column]
* AI output is a hypothesis.
* Human verification turns that hypothesis into an engineering decision.
* Validation is the constant across all design choices.

== AI Helper Versus AI Judgment

[.column]
* AI helps with boilerplate, patterns, and fast drafts.
* AI may miss deep races, ordering bugs, and state drift.
* AI can increase speed without increasing correctness.

[.column]
* Human review checks assumptions against code and tests.
* The engineer decides whether the evidence is strong enough.
* Correctness must survive load, retries, and timing changes.

== Trade-Offs

[.stretch]
[cols="1,1,1,1", options="header", width="100%"]
|===
|Approach |Strength |Weakness |Best use

|Simple baseline |Easy to explain |Hides pressure assumptions |First pass

|Guarded transition |Protects invariant directly |Needs careful state modeling |Status changes

|Explicit coordination |Makes ordering visible |May add waiting |Multi-object workflows

|Observability-first |Produces strong evidence |Adds instrumentation work |Defensible review
|===

== Practical Application

* Identify the invariant or progress property.
* Write one sequential success case.
* Write one pressure failure case.
* Add operation IDs and entity IDs.
* Capture before and after evidence.
* Update the Integrity Packet.
