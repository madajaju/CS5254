= Livelock vs Deadlock

== Opening Idea
* Two components each wait for the other to make progress.
* Logs can show activity while work never completes.
* The code may look locally reasonable.
* The coordination contract is still incomplete.
* The lecture asks what rule makes progress observable and defensible.

== Worked Example
* Two workers need a publishing slot.
* Each worker releases the slot to be polite.
* Each worker then retries at the same time.
* The workflow stays active but never finishes.
* A hallway example shows the same pattern.
* Both people step aside in the same direction repeatedly.

== Trade-Offs
[.stretch]
[cols="1,1,1,1", options="header", width="100%"]
|===
|Approach
|Strengths
|Weaknesses
|When to Use

|Simple baseline
|Easy to explain
|Hides pressure assumptions
|First implementation and comparison

|Guarded transition
|Protects the invariant directly
|Needs careful modeling
|Status changes and workflow steps

|Explicit coordination
|Makes dependencies visible
|Can bottleneck or deadlock
|Multi-object ordering

|Idempotent design
|Handles duplicates and retries
|Needs keys and deduplication
|Queues and external calls
|===

== Evidence to Capture
