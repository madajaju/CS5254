= Testing Coordination

== Framing the design pressure
* Testing coordination is about interaction, not isolated methods.
* The question is whether progress, ordering, and ownership still hold under pressure.
* A design is weaker when it only looks correct on the happy path.

== Trade-off summary

[.stretch]
[cols="1,1,1,1", options="header", width="100%"]
|===
|Approach |Strength |Weakness |Best use

|Simple baseline
|Easy to explain
|Hides pressure assumptions
|First pass

|Guarded transition
|Protects the invariant directly
|Requires careful state modeling
|Stateful workflows

|Explicit coordination
|Makes dependency visible
|Can introduce waits
|Multi-object steps

|Idempotent retry-safe design
|Handles duplicate work
|Needs deduplication
|Queues and callbacks
|===
