== Reproducible Execution

* Definition: Same workflow, same configuration
* Importance: Change silence complicates analysis
* Mechanisms:
** Versioned runtimes
** Scripts
** Containers
* Failure mode: Works on one machine
* Design implication: Essential runnable commands

== Two-Stack Repository Layout

* Definition: Separate implementations with conceptual parity
* Importance: Consistent object model in two environments
* Mechanisms:
** Shared documentation
** Separate directories
** Common scripts
* Failure mode: Implementations drift
* Design implication: Clear comparison necessary

== Structured Logging

* Definition: Consistent event records with key details
* Importance: Logs provide evidence for behavior
* Mechanisms:
** JSON or key-value logs
** Sorting and filtering capability
* Failure mode: Unable to trace changes
* Design implication: Design logging before failures

== Evidence Organization

* Definition: Predictable location for evidence materials
* Importance: Evidence must be reviewable
* Mechanisms:
** Standard folders
** Clear naming conventions
* Failure mode: Claims lack sources
* Design implication: Repo is integral to the system

== Worked Example: Problem Setup

* Domain: Podcast production
* Must run the same workflow:
** Create episode
** Process assets
** Mark episode ready
** Publish

== Naive Mental Model

* Code placed by preference:
** Java uses console text
** Node.js logs differently
* Issue: Inability to compare concurrency behavior

== Failure Scenario

* Five workers publishing the same episode:
** Java logs thread names
** Node.js logs request IDs
* Problem: Missing episode correlation ID
* Consequence: Inability to show equivalent failures

== Failure Modes and Anti-Patterns (1)

* Symptom: "It works on my machine."
** Cause: Undocumented setup steps
** Detection: Peer can't replicate
** Correction: Add version files or Docker

* Symptom: Logs are readable but not analyzable.
** Cause: Lacking correlation IDs
** Detection: Event order cannot be reconstructed
** Correction: Standardize early

== Failure Modes and Anti-Patterns (2)

* Symptom: Stacks evolve into different systems.
** Cause: Framework conventions dominate
** Detection: Object names and states differ
** Correction: Maintain shared models

* Symptom: Scattered evidence.
** Cause: Informal output capture
** Detection: Claims lack links
** Correction: Store evidence predictably

== Trade-Off Analysis

[cols="1,1,1,1", options="header"]
|===
| Approach | Strengths | Weaknesses | When to Use
| Manual local setup | Fast to start | Hard to reproduce | Early exploration only
| Dockerized setup | Consistent across machines | Adds overhead | When runtime drift matters
| Shared scripts | Repeatable commands | Maintenance required | Assignment demos
| Structured logs | Strong evidence | Requires discipline | For all concurrent workflows
| IDE-only execution | Convenient for debugging | Weak evidence | During debugging only
|===
