== Worked Example

* **Podcast Domain**:
  * Worker A reads `episode.status` (value: `DRAFT`).
  * Worker B reads `episode.status` (value: `DRAFT`).
  * Worker A sets status to `PROCESSING`.
  * Worker B sets status to `PROCESSING`.
  * *Result*: Duplicate work initiated.

* **Visual Mapping**: Vertical timeline mapping threads.

== Failure Scenario

* Overlapping execution can lead to stale state or executions.
* Not just a syntax bug; mismatch between design assumptions and execution.

== Corrected Design Direction

* Name the invariant, make transitions observable.
* Implement correctness controls: version checks, idempotency keys, state-machine guards.

== Trade-Off Analysis

[cols="1,1,1,1", options="header"]
|===
| Approach | Strengths | Weaknesses | When to Use
| Simple baseline | Easy to explain | Hides timing assumptions | Initial implementation comparison
| Guarded state transition | Protects core invariant | Requires careful modeling | Workflow steps and reservations
| Explicit coordination | Makes dependencies visible | Can introduce deadlock | Multi-object workflows
| Idempotent design | Handles duplicate work | Needs deduplication control | Queues, retries, external calls
| Observability-first design | Strong evidence for review | Adds instrumentation work | Assignments needing proof
|===
