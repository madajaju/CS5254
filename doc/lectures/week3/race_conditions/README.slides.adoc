* Design Implication: Expose invariant, log transitions, validate tests.

  * Worker A reads `episode.status` (value: `DRAFT`).
  * Worker B reads `episode.status` (value: `DRAFT`).
  * Worker A sets status to `PROCESSING`.
  * Worker B sets status to `PROCESSING`.
  * *Result*: Duplicate work initiated.

== Trade-Off Analysis

[.stretch]
[cols="1,1,1,1", options="header", width="100%"]
|===
| Approach | Strengths | Weaknesses | When to Use
| Baseline | Easy to explain | Hides timing | Initial comparison
| Guarded transition | Protects invariant | Needs modeling | Reservations
| Coordination | Visible dependencies | Deadlock risk | Multi-object flows
| Idempotency | Handles duplicates | Needs keys | Queues, retries
| Observability | Review evidence | Adds logging | Proof needed
|===

== Practical Application

* Enhance logs with operation IDs before testing.
* Capture before/after evidence when applying fixes.
