== Core Concept: Mutable Shared State

* Definition: Data accessed by multiple threads.
* Importance: Must be explicit for trusted system under pressure.
* Mechanisms: 
  * Object state
  * Workflow timing
  * Worker behavior
  * Queues
  * Coordination boundaries
* Failure Mode: 
  * Duplicate work
  * Stale state
  * Blocked progress
  * Misleading evidence
* Design Implication: Expose invariant, log transition, validate behavior.

  * Observes stale state.
  * Executes twice.
  * Workflow left stuck.
* Failure is a mismatch between assumption and execution.

== Failure Modes & Anti-Patterns

* Symptom: System passes single happy-path test.
  * **Detection**: Add repeated runs, concurrent actors.
* Symptom: Tool names precede design properties.
  * **Detection**: Ask which invariant is protected.
* Symptom: Evidence is vague.
  * **Detection**: Logs lack necessary identifiers or transitions.
* Symptom: Fix changes behavior without comparison.
  * **Detection**: No before/after repeatable scenario.

== Trade-Off Analysis

[.stretch]
[cols="1,1,1,1", options="header", width="100%"]
|===
| Approach | Strengths | Weaknesses | When to Use
| Baseline | Easy to explain | Hides timing | Initial pass
| Guarded transition | Protects invariant | Needs modeling | Status changes
| Coordination | Visible dependencies | Deadlock risk | Complex flows
| Idempotency | Handles duplicates | Controls effects | Queues, retries
| Observability | Strong evidence | Adds logging | Failure proof
|===
