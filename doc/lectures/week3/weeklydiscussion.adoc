----

state "Safe Update" as SafeUpdate

ConcurrentAccess --> SharedState : multiple actors mutate
SharedState --> OwnershipDecision

OwnershipDecision --> OwnedTruth : clear owner exists
OwnershipDecision --> Risk : no clear owner

OwnedTruth --> SafeUpdate : validate + synchronize
Risk --> SafeUpdate : add boundary, locks,\nserialization, or authority rules

SafeUpdate --> [*]

@enduml
----

[quote]
____
The hardest problem in concurrent systems is determining who owns truth when multiple things happen at once.
____

== Modules vs Objects

[plantuml,slide2,svg]
----
@startuml
title Modules vs Objects

skinparam shadowing false
skinparam roundcorner 18

rectangle "MODULES\n\nOrganize code\nUtility functions\nProcedural flow\nShared access" as Modules

rectangle "OBJECTS\n\nOwn state\nOwn lifecycle\nOwn invariants\nOwn authority" as Objects

Modules -right-> Objects : better boundary thinking

rectangle "BAD\n\nEnrollmentManager\nAircraftProcessor\nMatchingCoordinator\nWorkflowHandler" as Bad

rectangle "GOOD\n\nCourse owns truth\nAircraft owns identity/state\nBook owns ordering\nContentPackage owns lifecycle" as Good

Bad -right-> Good : move authority into objects

@enduml
----

[quote]
____
If your system only has Managers, Coordinators, Processors, and Handlers, you probably have procedural decomposition instead of object-oriented design.
____

== Discussion Questions

[%step]
* What object owns authoritative state in your system?
* What is the true concurrency boundary?
* Which object is most likely to become a god object?
* What failure would destroy trust in your system?
* What operational claim requires evidence?

== Closing Thought

[quote]
____
Good concurrent systems are not built from threads first.

They are built from:
- ownership
- authority
- lifecycle boundaries
- validation
- operational trust
____
