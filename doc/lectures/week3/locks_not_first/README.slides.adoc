== Failure Modes

* Symptom: happy-path success
  * Why: tests avoid pressure conditions
  * How to detect: repeated runs, delays
  * How to correct: add failure-focused tests

* Symptom: tool used, not design property
  * Why: focus on mechanisms, not invariants
  * How to detect: ask about the invariant 
  * How to correct: write invariant first

* Symptom: vague evidence
  * Why: logs lack detail
  * How to detect: reviewer fails to reconstruct
  * How to correct: capture structured evidence

* Symptom: fix without comparison
  * Why: failure not repeatable
  * How to detect: no before/after workload
  * How to correct: maintain failing test cases

== Trade-Off Analysis

[cols="1,1,1,1", options="header"]
|===
| Approach | Strengths | Weaknesses | When to Use
| Simple baseline | Easy implementation | Hides timing assumptions | First iteration
| Guarded transition | Protects invariant | Requires modeling | State changes
| Coordination | Makes dependencies visible | May cause bottlenecks | Object workflows
| Idempotent design | Handles duplicates | Needs keys for control | Queues, retries
| Observability-first | Solid evidence | Increases instrumentation | Failure proof requirements
|===
