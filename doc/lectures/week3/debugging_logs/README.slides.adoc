== Trade-Off Analysis
[.stretch]
[cols="1,1,1,1", options="header", width="100%"]
|===
| Approach | Strengths | Weaknesses | When to Use
| Baseline | Easy to explain | Hides timing | First pass
| Guarded transition | Protects invariant | Needs modeling | Status changes
| Coordination | Visible dependencies | Deadlock risk | Multi-object flows
| Idempotency | Handles duplicates | Needs keys | Queues, retries
| Observability | Review evidence | Adds logging | Failure proof
|===

== Practical Application
* Identify relevant invariant for debugging
* Write sequential scenario to succeed
* Create pressure scenario to expose failure
* Add operation IDs to logs
* Capture evidence for validation post-fix
