== Naive Implementation

actor performs operation
system reads current state

== Failure Scenario

* Overlapping execution can lead to:
  * Stale state
  * Duplicate execution
  * Workflow gets stuck

== Improved Design Direction

* Name the invariant
* Make transitions observable
* Introduce appropriate correctness controls:
  * Version checks
  * Idempotency keys
  * State-machine guards

== Why Improved Design Is Safer

* Ensures invalid interleavings are rejected, contained or recovered

== Failure Modes and Anti-Patterns

* Symptom: Passes happy-path demo
  * Detection: Add concurrent actors
  * Correction: Add failure-focused tests

* Symptom: Names tool but not design property
  * Detection: Ask which invariant is protected
  * Correction: State invariant first, then mechanism

* Symptom: Vague evidence
  * Detection: Reviewer can't reconstruct failure
  * Correction: Capture structured evidence

* Symptom: Fix changes behavior, but no baseline comparison
  * Detection: No before/after run
  * Correction: Preserve failing test and rerun 

== Trade-Off Analysis

[cols="1,1,1,1", options="header"]
|===
| Approach | Strengths | Weaknesses | When to Use
| Simple baseline | Easy implementation | Hides timing assumptions | First implementation
| Guarded transition | Protects invariant | Needs careful modeling | Status changes
| Explicit coordination | Makes dependencies visible | Introduces waiting | Multi-object workflows
| Idempotent design | Handles duplicate work | Requires control | Queues, retries
| Observability-first | Provides strong evidence | Adds instrumentation | Assignments requiring proof
|===
