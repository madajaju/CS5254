= AI Coordination Designs: Critique & Validation

== Opening Idea
* AI can produce a plausible coordination design
* Plausible is not the same as correct
* Under concurrency, hidden assumptions become failures
* Validation means stressing the invariant, not trusting the draft

== Trade-Offs
[.stretch]
[cols="1,1,1,1", options="header", width="100%"]
|===
|Approach |Strength |Weakness |Best Fit
|Simple baseline |Easy to build |Hides pressure assumptions |First draft
|Guarded transition |Protects invariant directly |Needs careful modeling |Stateful workflows
|Explicit coordination |Makes dependencies visible |May add waiting |Multi-step ordering
|Observability-first |Produces strong evidence |Adds instrumentation work |Validation and review
|===

== Evidence to Capture
* Correlation IDs
* Entity IDs
* State transitions
* Before and after runs
* Failure reproduction
* Trade-off discussion

== Practical Move
* Write the invariant first
* Create one happy-path test
* Create one pressure test
* Add structured logs
* Compare before and after
* Record the decision in the Integrity Packet

== A2 Connection
* Show the object, workflow, or event in your own domain
* Connect the failure to a concrete invariant
* Use evidence, not confidence
* Defend the chosen repair and its trade-off
