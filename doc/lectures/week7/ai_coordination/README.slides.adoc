== Coordination Hallucinations

* AI suggests patterns without event handling
* Critical to make conditions explicit under pressure
* Leads to duplicate work or blocked progress
* Must expose invariants and validate behavior

== Dependency Neglect

* AI may ignore necessary outputs between stages
* Trust issues arise without explicit conditions
* Risk of duplicate work or misleading evidence
* Ensure invariants are logged and validated

== Validation by Trace

* Trace AI logic with adversarial interleavings
* Identify deadlocks or missed signals
* Requires explicit conditions for trusted behavior
* Log transitions, validate with tests

== Coordination Boundary

* Agreement on ordering or progress among objects
* Vital to expose conditions before trusting system
* Failure leads to duplicate work or misleading evidence
* Design should log transitions and validate

== Progress Guarantee

* Shows work eventually completes, not waiting forever
* Explicit conditions necessary for trust under pressure
* Can lead to operational failures if ignored
* Design must log, validate transitions

== Worked Example

* **Podcast Domain**: AI proposes parallel threads, lacks join logic
* **Critique**: Assumes `notify()` follows `wait()` without guards

== Naive Implementation

* Assumes operations occur once, in order
* Often invisible due to method name correctness

== Failure Scenario

* Overlapping execution leads to stale state, blocked progress
* Mismatch between design assumption and execution

== Improved Design Direction

* Name the invariant, make transitions observable
* Introduce controls: version checks, state-machine guards

== Safer Design Benefits

* Proves invalid interleavings are rejected or contained
* Shifts focus from hope to evidence in execution

== Failure Modes and Anti-Patterns

* Symptom: Single happy-path test passes
  * Detect: Add stress conditions, concurrent actors
* Symptom: Tool mentioned, no design property stated
  * Detect: Ask for protected invariant
* Symptom: Vague evidence for claims
  * Detect: Log capture is insufficient
* Symptom: Fix alters behavior, lacks baseline comparison
  * Detect: No repeatable failure scenario preserved

== Trade-Off Analysis

[cols="1,1,1,1", options="header"]
|===
| Approach | Strengths | Weaknesses | When to Use
| Simple baseline | Easy to explain | Hides timing assumptions | Initial comparison
| Guarded transition | Protects invariant | Needs careful modeling | Workflow steps
| Explicit coordination | Visible dependencies | Risk of deadlock | Multi-object workflows
| Idempotent design | Handles duplicates | Requires deduplication | Queued operations
| Observability-first | Strong evidence | Adds instrumentation | Failure proof assignments
|===
